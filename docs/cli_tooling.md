# CLI Tooling & Benchmarking Guide

This document describes the command-line driver (`ely_cli`), REPL interactive shell, inspection flags, and automated performance benchmarking suite.

---

## 1. CLI Usage Reference

The CLI entrypoint is built into `tools/ely_cli`:

```shell
cargo run -p ely_cli -- [OPTIONS] [SCRIPT]
```

### Options and Flags

| Option / Flag | Description |
| :--- | :--- |
| `[SCRIPT]` | Path to an Elysabettian source file (`.ely`). If omitted, launches interactive REPL. |
| `--jit` | Forces pure Just-In-Time native compilation via Cranelift for top-level code. |
| `--no-jit` | Forces bytecode VM interpretation (disables dynamic JIT promotion). |
| `--dump-ir` | Prints Cranelift Intermediate Representation (SSA IR) during compilation. |
| `--dump-asm` | Prints native machine code disassembly (VCode) generated by Cranelift. |
| `-h, --help` | Displays help message and CLI options. |
| `-V, --version` | Displays version information. |

---

## 2. Interactive REPL

Running the CLI without script arguments starts the interactive REPL:

```shell
cargo run -p ely_cli
```

### JIT Native REPL
To run the REPL directly in Cranelift JIT mode:

```shell
cargo run -p ely_cli -- --jit
```

```text
Elysabettian REPL (v0.1.0) [JIT Native Mode]
Type 'exit' or press Ctrl+D to exit.

ely> var x = 10;
ely> var y = 25;
ely> print x * y + 5;
255
ely> print "Elysabettian Native JIT!";
Elysabettian Native JIT!
```

**Features:**
- Persistent command history across sessions (stored in `~/.ely_history`).
- Arrow-key line navigation, Ctrl+A/E, and Ctrl+C cancellation via `rustyline`.
- Dynamic global variable updates and immediate expression evaluation.

## 3. Scientific Performance Benchmarking Suite

An automated statistical benchmarking tool is provided in [`tools/benchmark.py`](../tools/benchmark.py):

```shell
python3 tools/benchmark.py
```

### Benchmark Methodology & Workloads
The suite runs 5 diverse algorithmic workloads:
- **`bench_loop.ely`**: Simple accumulator loop (2,000,000 iterations).
- **`bench_arithmetic.ely`**: Transcendental math ($+, -, *, /$ with $\pi$ and $e$, 2,000,000 iterations).
- **`bench_fibonacci.ely`**: Iterative Fibonacci with register shifts (1,000,000 iterations).
- **`bench_leibniz_pi.ely`**: Leibniz infinite series for $\pi$ with alternating sign (5,000,000 iterations).
- **`bench_collatz.ely`**: Collatz 3n+1 trajectory steps with bitwise shifts (25,000 ranges).

Each test runs **2 warmup iterations** followed by **5 timed evaluation runs**. The tool calculates:
- Sample Mean ($\mu$)
- Sample Standard Deviation ($\sigma$)
- Speedup factor ($\mu_{VM} / \mu_{JIT}$)
- Bit-exact numerical result verification between VM and JIT.

### Graphical Artifacts & Reports
Outputs are automatically written to `tools/results/`:
- `benchmark_execution_times.png`: Grouped bar chart comparing Mean Execution Times with $\pm \sigma$ error bars.
- `benchmark_speedup.png`: Horizontal bar chart of Cranelift JIT speedup factors across all workloads.
- `BENCHMARK_REPORT.md`: Comprehensive Markdown report with summary tables.
- `benchmark_data.json`: Raw benchmark metrics for further analysis.

## 4. Pre-Compiled Binaries & CI/CD Release Pipeline

Automated continuous integration and release workflows are configured in [`.github/workflows/`](../.github/workflows/):

| Target | Architecture | Distribution | Format |
| :--- | :--- | :--- | :--- |
| `x86_64-unknown-linux-musl` | 64-bit x86 | Any Linux distribution (Static, zero glibc dependency) | `.tar.gz` |
| `x86_64-unknown-linux-gnu` | 64-bit x86 | Linux (glibc dynamic) | `.tar.gz` |
| `aarch64-apple-darwin` | 64-bit ARM | macOS Apple Silicon (M1/M2/M3/M4) | `.tar.gz` |
| `x86_64-apple-darwin` | 64-bit x86 | macOS Intel | `.tar.gz` |
| `x86_64-pc-windows-msvc` | 64-bit x86 | Windows 10/11 / Windows Server | `.zip` |

### Triggering Releases
- **Automatic:** Pushing any version tag matching `v*` (e.g., `git tag v0.1.0 && git push origin v0.1.0`) automatically builds all targets, generates `SHA256SUMS.txt`, and publishes a GitHub Release with attached assets.
- **Manual (`workflow_dispatch`):** Runs the workflow from the GitHub Actions web interface on any commit, allowing ad-hoc or nightly builds without creating a tag.
